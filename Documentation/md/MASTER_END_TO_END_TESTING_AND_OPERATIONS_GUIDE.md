## 1. Executive Summary & Live Endpoints

## 3. Web & Mobile App Testing Runbook

### 3.1 Web Client Sign-In Flow
1. Open [`https://networkpeer-platform.vercel.app/auth`](https://networkpeer-platform.vercel.app/auth).
2. Notice the **+91 badge** is locked and non-editable.
3. Enter your 10-digit phone number (e.g. `9876543210`).
4. Click **Send Verification Code**.
5. When the 6-digit input appears, enter the code received on your phone or read from CloudWatch.
6. Click **Verify and Continue**. You are redirected into the Client Dashboard (`/client`).

### 3.2 Mobile Worker App Testing (Mac M1 via USB Cable)
1. **Enable Developer Mode on Android Phone**:
   - Go to **Settings** > **About Phone** > tap **Build Number** 7 times.
   - Go to **Settings** > **Developer Options** > enable **USB Debugging** and **Install via USB**.
2. **Connect Phone to Mac M1**:
   - Connect via USB-C cable. On the phone, select **Always allow from this computer**.
3. **Verify Device Connection**:
   ```bash
   adb devices
   ```
4. **Reverse Local Ports**:
   ```bash
   adb reverse tcp:8081 tcp:8081
   adb reverse tcp:8787 tcp:8787
   ```
5. **Launch Worker App**:
   ```bash
   cd apps/mobile
   npm run android
   ```
6. **Sign In**:
   - The worker app displays the **+91 badge**.
   - Enter your 10-digit mobile number and submit.
   - Input the verification OTP code.

## 4. End-to-End Feature Verification Lifecycle

### 4.1 Step 1: Post a Job (Client)
1. Go to **Client Dashboard** > **Post New Job** (`/client/jobs/new`).
2. Fill out the multi-step job wizard:
   - **Title & Description**: e.g., "Storefront Inspection & Signage Verification".
   - **Category**: Retail / On-Site Inspection.
   - **Location**: Click on the interactive map or enter coordinates.
   - **Budget**: Set task payment (e.g., ₹500).
   - **Required Evidence Subtasks**: Photo of entrance, Video of aisles, GPS location stamp.
3. Submit and confirm escrow funding. The job transitions from `FUNDING` to `POSTED`.

### 4.2 Step 2: Discover & Accept Job (Worker)
1. In the Android app, open the **Available Tasks** tab.
2. Nearby jobs appear sorted by proximity distance bands (`UNDER_1_KM`, `1_TO_5_KM`, etc.) without exposing private client info.
3. Tap the job to view details and tap **Accept Job**.
4. The job status transitions to `ASSIGNED`, and the exact address is unlocked for the worker.

### 4.3 Step 3: Capture & Upload Tamper-Proof Evidence
1. The worker arrives on site and taps **Start Task** (`IN_PROGRESS`).
2. Taps **Capture Evidence** for each subtask:
   - Takes a live camera photo or video.
   - The app stamps device EXIF data, timestamp, and high-accuracy GPS coordinates.
   - Computes SHA-256 hash of the media file locally.
   - Uploads directly to S3 via presigned POST credentials.
3. Taps **Submit for Review** (`SUBMITTED`).

### 4.4 Step 4: Review & Escrow Release
1. The client opens the **Review Studio** (`/client/review/:jobId`).
2. Inspects side-by-side evidence images/videos stamped with map coordinates.
3. Clicks **Approve Job**.
4. The backend database automatically transfers escrowed funds from the client's balance to the worker's wallet (`COMPLETED`).

### 5.1 Connecting to RDS PostgreSQL via Desktop GUI (TablePlus / DBeaver)
For a professional presentation, use **TablePlus** (Mac-native, fast) or **DBeaver Enterprise**.

- **Host**: `networkpeer-staging-postgis.c7e6uqswai46.eu-north-1.rds.amazonaws.com`
- **Port**: `5432`
- **User**: `postgres` (or your IAM database user)
- **Database**: `networkpeer`
- **Key Tables to Demonstrate**:
  1. `users`: Identity records, roles (`CLIENT`, `WORKER`, `ADMIN`), and phone numbers.
  2. `jobs`: Core job state machine (`POSTED`, `ASSIGNED`, `COMPLETED`), geometry points, and budgets.
  3. `job_subtasks`: Granular requirements per job.
  4. `job_subtask_media`: S3 keys, SHA-256 hashes, and verified GPS coordinates.
  5. `escrow_accounts` & `escrow_transactions`: Cryptographic financial ledger.
  6. `audit_logs`: Immutable security log of every state change.

> **Spatial Map Demonstration**:

## 7. Troubleshooting & Emergency Operations

1. **OTP Not Arriving via SMS**:
   - Run `aws logs tail /aws/lambda/networkpeer-staging-cognito-custom-auth --region eu-north-1 --since 1m` to instantly get the code.
   - Complete website verification in the Fast2SMS portal.
2. **Restarting Backend API on ECS Fargate**:
   ```bash
   aws ecs update-service --cluster networkpeer-staging-cluster --service networkpeer-staging-api --force-new-deployment --region eu-north-1
   ```
3. **Running Fresh Database Migrations**:
   ```bash
   cd NetworkPeer-main
   DATABASE_URL="postgres://postgres:<PASSWORD>@networkpeer-staging-postgis.c7e6uqswai46.eu-north-1.rds.amazonaws.com:5432/networkpeer" npm run migrate
   ```
